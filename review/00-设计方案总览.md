## 1. 用户真实需求（原话归纳）

1. 纯净版**绝不能含成人内容**。
2. 要能**在首页按分类筛选**片子。
3. 要**高清晰**（用户明确说平铺点开的高清片是能看的）。
4. 要**能搜索片名**，且搜出来的是**匹配的片**，不是固定片单。
5. 用户只记两个地址：**完整版** 和 **纯净版**。

| 事实 | 证据 | 来源 |

| 新6V详情页含 magnet/网盘链接 | 详情页提取到 `magnet:?xt=urn:btih:...` 及 quark/aliyun 链接 | curl_cffi 实测 |

## 3. 设计方案

### 3.1 核心思路
用 **Cloudflare Worker**（免费云函数）做一层"网页 → 苹果CMS JSON"的翻译：

```
用户客户端(影视仓)
   ↓ ac=detail&wd=片名
Cloudflare Worker (hdsearch)
   ↓ POST /e/search/so.php
新6V / dyg7 (帝国CMS网页)
   ↓ HTML
Worker 解析HTML → 组装成苹果CMS JSON → 返回客户端
```

### 3.2 交付物
- `worker.js` — 转换器完整实现（162行）
- `API_SPEC.md` — 完整接口规范
- `EVIDENCE_AND_CONTRADICTIONS.md` — 证据链 + 矛盾清单
- `01-当前配置快照.md` — 线上配置与来源
- `deploy.js` — 一键部署脚本

### 3.3 设计目标
- 首页分类筛选：Worker 提供 `ac=list` 返回标准分类表
- 精确搜索：`ac=detail&wd=` 返回匹配片名+封面
- 成人过滤：分类黑名单 + 片名黑名单
- 免费、无需信用卡、无需自建服务器

## 4. 已知风险与未验证项（重点，请第三方重点评估）

| # | 风险 | 严重度 | 说明 |
|---|---|---|---|
| R1 | **workers.dev 国内可能连不上** | 高 | 本机实测 DNS 解析成功但 443 连接超时（21秒）。临时账号部署的 `hdsearch.impossible-harpymimus.workers.dev` 在本机不可达。需验证电视网络环境下是否可达；可能需要绑定自定义域名。 |
| R2 | **提取的播放链接能否被 TVBox 播放，未验证** | 高 | 用户说"平铺点开能看"，但转换器提取的是 magnet/网盘原始链接，与客户端原生 csp 插件的播放流程是否一致**未经真机验证**。这是本方案最大的未验证点。 |
| R3 | **HTML 正则脆弱** | 中 | `parseList` 依赖 `href...img src...alt` 的固定顺序和 900 字符窗口。帝国CMS改版会导致解析失效。 |
| R4 | **CAT_MAP 有重复键** | 低 | `'电视剧'` 在映射表里出现两次（值为'2'和'19'），wrangler 部署时报警告，后者覆盖前者。需修正。 |
| R5 | **成人过滤只靠关键词** | 中 | 黑名单匹配片名/分类，可能漏判（如片名不含敏感词的成人内容），也可能误伤（如"肉"字出现在正常片名）。 |
| R6 | **搜索分页/排序未实现** | 低 | `pagecount:5` 是硬编码，未真实解析总页数。 |
| R7 | **目标站反爬/Cookie** | 中 | 若 xb6v 加验证码或 Cookie 校验，Worker 的 fetch 会失败。本机测试时未遇到，但长期使用有风险。 |
| R8 | **临时账号60分钟失效** | 高（若不认领） | 已用 `--temporary` 部署过一次，地址60分钟后失效。正式使用必须用用户自己的 Cloudflare 账号部署。 |

## 5. 需要第三方回答的核心问题

1. **方案是否成立？** 用云函数把网页转苹果CMS接口，是当前约束下唯一可行路径吗？有没有更简单的方案被遗漏？
2. **R2 风险如何验证？** 在不部署到正式账号的情况下，如何提前确认"转换器提取的 magnet 链接"能被用户客户端播放？
3. **R1 风险如何规避？** workers.dev 国内不可达时，除了自定义域名还有什么办法？
4. **成人过滤是否足够？** 关键词黑名单是否是可靠方案？
5. **是否应该放弃磁力源？** 考虑到播放不确定性，是否应该只保留在线 m3u8 源（醉影类）？
